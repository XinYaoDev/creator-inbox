# 2026-10-18 专项验收：多轮销售接待与本地向量检索

## 结论与范围

本轮补齐两个优先项：可配置、持久化的多轮销售接待，以及不需要额外密钥的本地中文向量检索。原生 Laike AI 已载入更新，不只是源码或浏览器预览变更。

对照 [来鼓成交转化](https://laigu.com/agent/conversion) 公开的需求理解、顾虑回应和交接能力，实现本地可验证的链路；没有复制其私有实现，也不宣称全量商业功能等价。新增功能不依赖社交平台授权。GPT 继续通过本机 Hermes → Codex 使用已保存的 `gpt-6.1-sol`，没有读取或复制登录令牌到业务数据。

所有测试顾客与青禾陶艺资料均为合成内容，真实模型与网页访客接口在本机运行；没有向真实顾客发消息、创建真实预约、支付或公开部署。

## 真实八轮接待

使用 Safari 的独立访客页面，自动回复经实际 Hermes/GPT 调用，全部收到访客回执。没有用沙箱注入接口、预制模型回复或修改时钟替代。

会话 `cb91b506-20cb-48f2-bc74-5358a870327c`，名称「多轮复验访客」，16:09–16:17（北京时间）：

| 轮次 | 访客输入要点 | 实际结果 |
| --- | --- | --- |
| 1 | 周末和朋友首次做陶艺，问适合哪个 | 推荐知识中的基础手捏 129 元/2 小时，说明包含项目；只问人数，不因最终需人工核位而提前中断。 |
| 2 | 四个人、周日下午，空手去是否要带装备 | 命中材料工具知识，说明无需自备；记住人数和时间，只问预算。 |
| 3 | 每人最多 150 元，仍嫌贵，电话微信暂不留 | 解释费用包含项、无团购折扣；不强迫留资、不追加问题；记录价格顾虑与拒绝留资。 |
| 4 | 改三个人、下周六上午，价格可接受，询问寄送 | 正确替换旧人数和时间，价格顾虑标记解决；寄送每件 20 元，按每人一件条件计算 149 元/人；只发一次交接确认。 |
| 5 | 问有无老师，仍想比较 | 依据知识回答有老师指导，不催促，进入暂停推进。 |
| 6 | 明确暂不推进 | 回复尊重考虑，不追问、不自动转成交。 |
| 7 | 恢复咨询，回忆人数/时间/预算 | 准确回忆三人、下周六上午、每人最多 150 元及首次体验；明确尚未预约。 |
| 8 | 明确同意交给同事核实 | 转人工，保留确认原话与完整摘要，创建一条跟进待办；客户阶段仍是 `new`。 |

第 3 轮后实际重启服务，再完成第 4 轮，记忆和本地模型缓存正常恢复。交接后继续发送“后续等同事确认，请不要自动回复”，没有新增 AI 回复；再次重启服务、刷新访客页面后仍为人工接待，8 条模型回复和历史保留。

团队界面实际检查：档案 v8、8 条接待轨迹、拒绝留资、已解决价格顾虑、可复制摘要、`gpt-6.1-sol` 及回答时本地向量引用版本。上述内部档案不返回访客 API。

## 真实向量验收

本地 `@huggingface/transformers` + ONNX Runtime 实际编码，不是随机向量、哈希向量或模拟 Embeddings。固定权重、许可与缓存说明见 [模型声明](LOCAL-EMBEDDINGS-NOTICE.md)。首次真实下载缓存约 23 MB；冷进程可从缓存加载，正常查询禁止自动联网下载。知识及查询在本机编码，但 GPT 生成仍会接收对话和检索到的业务内容。

`node scripts/verify-local-retrieval.mjs` 使用内存数据库、真实本地模型验证：

| 查询 | 首条结果 / 实测相似度（约值） |
| --- | --- |
| 空着手过去就行吧，不用带装备？ | 材料工具 / 0.458 |
| 烧好以后能送到我家吗？ | 作品领取与寄送 / 0.586 |
| 没碰过泥巴的小白选哪个？ | 基础与进阶体验 / 0.405 |

| 汽车发动机火花塞怎么更换？ | 无命中 |

还验证了修改知识后旧索引失效、重建引用 v2、停用后不再召回。原生桌面在服务重启后实际查询“礼拜天最晚几点还能过来参观？”，语义匹配“周末预约与营业时间”v1，相似度 0.474，本地索引为 1/1。

这是小样本验收，不是质量基准。默认门槛 0.40 是当前测试资料的召回折中，靠近门槛的结果尤其需要业务样本校准；相似度不是答案正确率。当前为 SQLite 持久化与精确向量扫描，不是大规模 ANN 检索服务。云 API 向量接口仍只有适配/异常测试，本轮真实使用的是本地模型。

## 实测发现后修正

1. 首次真实访客发现 GPT 把普通周末意向也提前转人工：补充“意向了解”和“实时余位/执行请求”的边界与例子，再跑完上述八轮。最初失败会话保留，未计为通过。
2. Transformers 管线冷启动存在离线缓存发现问题：改用固定版本的 tokenizer/model 显式加载，直接读取已缓存版本目录，重新验证冷进程与服务重启。
3. 内置浏览器的系统确认框阻塞后续操作：新咨询与需求重置改为页面内确认，真实验收改用独立 Safari 并通过，未借此退回模拟测试。
4. 人工回复、访客申请人工、完成和模型失败同步需求阶段；未实际问出的问题不记入“已问”；重置后新上下文与旧历史隔开。
5. 检索结果标签浮动把正文挤窄：取消浮动，标题/标签/正文分行、正文 13px 和更深文字色、移除片段内截断滚动。

### 桌面可读性小复查

结论：原检索结果需要改进；没有进行完整无障碍认证。问题是次要相似度标签挤占知识正文。依据桌面设计技能的 Layout“为重要内容提供足够空间”和 Typography“狭窄区域采用堆叠布局”，采用分行信息层级；提高正文可读性，保留文字状态，不单靠颜色表达命中方式。原生客户端重新加载后检查，正文不再被标签压窄。
