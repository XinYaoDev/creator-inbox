# 内置桌面运行环境与报错修复 — 2026-10-18

## 已实现并验证

- Tauri 客户端自带 Node 22.23.1、生产后端、前端、运行依赖及已下载的本地检索模型缓存。当前安装包约 628 MB，未作为包体优化完成来宣传。
- 原本的 `18877` 开发服务已停止。客户端现在只启动自己的子进程，使用可用的本机随机端口；退出客户端会关闭所属后端，不结束其他服务。
- 本机服务仅监听回环地址。每次启动独立会话票据，HttpOnly / SameSite=Strict cookie、Host 与 Origin 检查；远程页面没有本机维护指令权限。
- 内置启动与维护面板：启动阶段、程序校验、数据库检查、版本、运行环境、数据位置、安全诊断导出、重启、签名更新、回滚。快捷键 `⌘ ,`，单独窗口，不替换正在编辑的工作台。
- 签名更新包使用 Ed25519 验签及逐文件 SHA-256 校验，限制路径、文件总量、设备架构和数据兼容版本。签名私钥未打入客户端。失败或截断包不切换现有程序。
- 切换版本前使用 SQLite 在线备份；候选版本通过实际启动、身份健康检查及短暂稳定性检查后才提升为当前版本。启动失败自动恢复原版本。手动回滚保留当前业务数据，不用旧备份覆盖新记录。
- 当前运行目录迁移到 `/Users/xinjiang/Library/Application Support/com.yuejing.laike/data`。原 `data/growth-acceptance` 目录保留，记录分组计数与保存模型设置数量一致；原连接使用 Hermes，不存在需要复制的 API 密钥文件。

## 真实验收抓到并修复的问题

1. WebKit 从 `tauri://` 跳转的重定向链不携带 Strict cookie，首次启动出现“请从来客桌面客户端打开本机工作台”。改为先提交同源连接页，再替换为工作台页面，保留严格 cookie 策略。桌面冷启动已实际进入工作台。
2. 独立启动没有继承终端代理环境，导致 Hermes / GPT 连接失败。补充继承显式代理变量，以及从 macOS 读取已经启用的本机回环代理，不选择新的外部代理，也不修改系统设置。
3. 维护后随机端口变化，原窗口留在旧服务会出现 `Load failed`。本机维护操作确认后，在服务就绪时自动重连主窗口；失败恢复时维护面板仍保留错误说明。
4. 为防止替换原生安装包改变“上一版”的含义，首次切换前会冻结内置业务版本，回滚使用不可变的已验证目录。

## 范围与边界

此处的签名更新与回滚覆盖业务前端和后端。原生壳及内置 Node 运行时更新仍通过完整客户端安装包，不宣称已有联网自动下载更新或原生二进制自动回滚。代码回滚仅接受当前声明的数据兼容版本；历史数据库备份不会自动覆盖当前业务记录。

保留原项目的安全边界：没有启用真实平台账号自动发送，没有修改 Hermes 登录，没有读取或导出登录令牌。超大文件流式导入和知识来源持续同步仍是后续待完成项；现有文本批量导入仍为 700 KB / 200 条上限。

桌面布局和恢复反馈按 Apple 桌面设计与无障碍检查组织，保留键盘焦点、文字状态、明确的维护确认、真实解包进度和失败恢复路径；不代表完成了全面无障碍认证。
