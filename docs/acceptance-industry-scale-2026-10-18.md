# 2026-10-18 多行业销售与规模知识检索验收

## 结论和范围

本轮补齐六行业接待模板、按分类限定员工知识、分页与批量知识管理、可中断续建的后台索引，以及多轮接待中的引用连续性和明确排除项。原生 Laike AI 客户端已实际载入更新，主服务仍在 `127.0.0.1:18877`。

162 项自动测试通过。另以真实本地 BGE 模型检索 3,018 条合成知识、6,006 个片段，168 个检索回归用例通过；六行业最终一轮共 48 次真实 GPT 接待调用通过预设行为检查。网页访客实测另外发现并修复了交接档案错误，最终两轮回归的回复、需求、排除项、人工交接和访客回执均正确。

这些结果证明本机实现和本批回归链路可用，不等于生产准确率或来鼓全量商业功能等价。资料、商户、顾客均为隔离合成数据；没有真实客户外发、预约、支付、平台授权或公网部署。GPT 沿用本机 Hermes → Codex 的 `gpt-6.1-sol`，没有复制登录令牌到项目。

## 本轮功能

| 能力 | 实现及边界 |
| --- | --- |
| 行业模板 | 通用接待之外，提供住宿民宿、商品零售、上门服务、成人课程、企业软件、体验活动六个模板。独立需求字段、默认追问和行业边界；应用后须保存，不改变品牌、知识范围、渠道或启用状态。 |
| 多轮推进 | 区分需求偏好与保证/执行请求；不会仅因颜色、日期等意向提前终止接待。价格顾虑解决不清空其他顾虑，暂停、恢复、拒绝留资仍有效。 |
| 回答依据延续 | 最多保留 8 条当前仍有效的引用，检查版本、启用、归档和员工范围；不再因为恢复咨询时缺少关键词就撤回先前有依据的介绍。 |
| 排除项 | 核心需求与明确不要的项目分开保存；当前顾客原话、字段白名单和否定前缀校验。交接同轮也输出排除项；明确撤回原值或重新选择同一项目单独处理。 |
| 员工知识范围 | 分类自动包含其后续启用资料，分类与逐条选择取交集；逐条最多 500 条、分类最多 50 个。选择器搜索仅展示前 50 条。 |
| 分页和批量审核 | 每页默认 50 条，正文按页或详情读取；批量启用、停用、归档、恢复先显示选中范围，一次最多 100 条。全部版本核验后事务提交，冲突整批拒绝；恢复默认停用，保留历史。 |
| 后台索引 | 服务端连续处理 32 片段批次；离开页面不影响进度；本批后暂停、失败重试、服务中断后明确续建，只计算缺失片段。更换模型会拒绝旧任务结果。 |
| 检索 | 本地句子分片、归一化向量缓存、关键词倒排、可见的行业口语扩展、编号保护和弱证据弃答。精确扫描每 512 片段让出执行时间；不是 ANN。 |

## 知识规模和检索结果

固定资料包括六行业共 18 条现行业务事实及 3,000 条带不同编号、城市、规格、数量、预算和月份的历史干扰资料，每行业 500 条。它比少量演示数据更能暴露排序和错误编号匹配，但仍是模板化合成语料，不代表真实长文分布。

本地模型为固定版本 `Xenova/bge-small-zh-v1.5`，512 维 q8，阈值 0.40。片段策略 `sentence-chunks-v3`，最终 6,006/6,006 就绪。模型及许可详见 [本地向量声明](LOCAL-EMBEDDINGS-NOTICE.md)。知识和查询在本机编码，GPT 生成仍接收对话及相关知识。

| 查询组 | 数量 | 最终通过 | 正确资料排名指标 |
| --- | ---: | ---: | --- |
| 行业口语校准集 | 72 | 72 | Recall@4 100%，MRR 0.948 |
| 精确编号 | 36 | 36 | 全部首条正确 |
| 无关问题校准集 | 12 | 12 | 全部无命中 |
| 追加正向留出集 | 36 | 36 | 首次及最终 Recall@4 100%，最终 MRR 0.986 |
| 追加负向留出集 | 12 | 12 | 首次 11/12，修复后作为回归集 12/12 |

通过定义：正向查询预期资料出现在前四名；负向查询不返回资料。不是整段回答正确率。评估方式参考 [OpenAI 评估最佳实践](https://developers.openai.com/api/docs/guides/evaluation-best-practices)，将典型、边界、无关问题及独立追加用例分开。**看过留出失败并修复之后，同一组满分只能称回归通过，不能继续声称独立泛化成绩。**

### 失败记录和修复

| 实测问题 | 原结果 | 修复与复查 |
| --- | --- | --- |
| 大量历史资料挤占正确答案 | 初轮口语 69/72，编号虽在前四但 MRR 0.699 | 改善分片与融合，避免弱关键词压过强语义；严格编号匹配，通用保修政策仍可用于对应型号。 |
| 口语和弱语义误召回 | 分片后仍有 68/72 正向、10/12 负向 | 增加透明业务概念扩展与保守弃答，保留阈值局限。 |
| 中文连词跨词误匹配 | 首次追加负向 11/12；“欧拉公式与复平面的关系”误中“课程形式与课时” | 排除跨常见连词的二字片段，避免“式与”等偶合；最终 168 个用例回归通过。 |
| 恢复咨询错误撤回已知介绍 | 早期零售、企业软件等会话出现“此前缺乏依据” | 保留并重新核验历史引用，六行业完整 48 次调用复查。 |
| 排除项覆盖需求 | 网页会话把“地面和厨卫日常保洁”替换成“不增加油烟机拆洗” | 核心需求与限制分离；首次回归虽保住需求但遗漏限制，随后补充结构化排除项协议，最终真实网页回归通过。旧失败会话保留。 |

原始阶段结果保存在验收目录的 `retrieval-before-ranking.json`、`retrieval-before-calibration.json`、`retrieval-first-holdout.json`、`sales-before-fixes.json` 和 `sales-before-context.json`，不将失败结果删除或算成通过。

### 本机延迟

最终一次 HTTP 实测中，不同查询序列 P50 6.90 ms / P95 10.75 ms；重复查询 P50 3.64 ms / P95 5.13 ms。4 个并发客户端共 40 次请求 P95 15.94 ms，同时查询索引状态 P95 6.18 ms。

上述为已建索引、固定本机环境的检索请求延迟，不含 GPT 回复、首次权重下载和完整冷启动；不是公网延迟、持续压力测试或生产 SLA。当前仍按符合范围的向量精确扫描，万级以上容量、长文分布和高并发未验收。

## 真实 GPT 和网页流程

最终六行业各执行七轮：首问 → 补全条件 → 修正需求 → 价格顾虑 → 暂停 → 恢复并拒绝预算/联系方式 → 明确同意交接。每行业另有一次未知实时执行问题，共 48 次真实 GPT 调用，不使用模型替身。这组通过沙箱业务 HTTP 入口调用实际模型，不能冒充浏览器输入；额外网页实测见下方。

六行业均通过：完整七轮、字段修正、暂停、拒绝留资、人工交接、新线索阶段保持、模型来源记录、未知执行转人工、未自动成交，以及不再撤回已有依据的介绍。软件对接、库存、房态、排期和名额未知时均未承诺已落实。完整回复及每轮状态保存在 `sales-report.json`。

真实网页接待在内置浏览器进行，接待台在另一个标签页检查：

1. 合成访客提出西湖区下周六日常保洁、是否自备工具。GPT 正确回答工具由保洁员带。
2. 改为拱墅区，暂停，拒绝预算/电话/微信。修正与拒绝意愿保留。
3. 恢复咨询，确认工具及油烟机拆洗。回答自备工具政策延续，拆洗不属于日常范围。
4. 同意人工核实且不增加拆洗。正确转人工，但检查档案发现需求被排除项覆盖；此会话保留为失败证据。
5. 修复后新建会话复测两轮，需求不再丢失，但限制未独立记录；继续修复。
6. 最终新建「排除项完整回归访客」：两轮真实 GPT、两条访客回执；同时保存“地面和厨卫表面日常保洁”与“不增加油烟机拆洗”，交接摘要包含双方原话，恰好一条待办，客户阶段仍为新线索。

最终会话 ID：`10286744-37e9-4e87-ab80-979e251c92a6`。`scripts/verify-industry-web.mjs` 只读取这次浏览器会话，验证 11 项断言，不注入消息、不调用模型、不修改时钟。内部需求档案和引用仍不进入访客 API。

六行业最终批次在排除项协议补充之前完成；协议补充后重新执行全部 162 项自动测试，并完成上述真实网页两轮专项回归，没有宣称对每次小修都重跑 48 次模型调用。
