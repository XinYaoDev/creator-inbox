# 无平台授权能力收口：实际结果与边界

本轮以独立桌面客户端 `Laike AI Acceptance.app` 验收，不向真实客户发消息、不进行支付、不复制正式客户记录或 Hermes 登录令牌。正式库与隔离库使用不同应用标识。既有功能及此前真实流程见各专项报告，本文件只记录新增结果。

## 130319 条公开资料的磁盘检索

完整 SQuAD 2.0 语料（来源、许可和哈希见大文件报告）进入新的隔离 SQLite 数据库并全部启用。超过 5000 条启用知识后，使用持久 FTS5 倒排、分批片段目录与分页精确向量扫描；不再在每次请求加载全量正文和向量，不称作 ANN。

实测暴露数据库优化器从业务记录出发逐条探测全文索引，早期长跑因此中止，未将其算作通过。修复为从 FTS 命中集合开始，统计按数据代次缓存，英文完整词查询排除无意义碎片；之后复用同一完整索引重跑。

| 检查 | 实测 |
| --- | --- |
| 数据条目 | 130319，完整公开真实语料，不是重复填充 |
| 抽样 | 每 263 条抽 1 条，496 个原始问题 + 496 个精确编号 |
| 找回对应条目 | 原问题 496/496 Top4；编号 496/496 Top4 |
| 原问题检索延迟 | P50 33.68 ms；P95 76.16 ms；最大 123.60 ms |
| 内存 | 512 MiB 堆上限运行，进程峰值 RSS 259.91 MiB |
| 索引 | 138144 个片段目录；本批为倒排查询，未为十三万条全部计算向量 |

问题来自被索引资料标题，因此这是容量、原问题查找与编号正确性检查，不是独立语义泛化评估。复用索引的约 2.9 秒就绪时间不代表首次全量建索引时间。原始结果：`data/large-source-acceptance-20261018/retrieval-iOsDJI/report-optimized.json`。

另以真实本地 BGE 查询验证磁盘向量路径：原 3018 条合成行业资料的 6006 个真实向量，加 2000 条公开英文干扰资料，共 5018 条启用资料。24 个中文查询全部命中预期前四条，P50 818 ms、P95 1366 ms、峰值 RSS 320 MiB。显式型号查询先按型号过滤，实际比较 352 个向量；其他查询比较 6006 个。初始测试误把型号过滤也要求扫描 6000 条，修正测试条件后复跑，不属于检索算法失败。新增英文干扰资料未向量化，不能据此宣称完成十三万条全向量压力验收。结果：`disk-vectors-o7h2xf/report.json`。

## 本地业务执行与真实桌面流程

新增管理员专用「本地业务台」：商品与库存、资源时段、报价、订单、预约、业务统计。金额用人民币整数分；库存预留与履约扣减分开；同资源时段禁止重叠；版本冲突、幂等请求、容量不足均在服务器事务内校验。无外部支付或平台交易，最终动作需明确确认。

实际通过原生桌面点击完成：

1. 商品 DESK-001，单价 129 元、库存 5。
2. 129 元报价草稿 → 确认报价 → 记录接受 → 仅一次转为订单草稿 → 确认订单，库存预留 1，可用 4。
3. 第二张 5 件订单尝试确认，被库存不足拦截，未扣减任何商品。
4. 取消第一单，预留回到 0、可用回到 5；再确认第二单并履约，库存变为 0，预留变为 0。
5. 时段 A 容量 2，时段 B 容量 1。A 的两人预约确认后，改期到 B 被拒绝，A 仍保留两人预约。将 B 容量改为 3 后，改期成功；取消预约，A/B 已确认数均回到 0。
6. 统计显示取消订单 1 单 / 129 元、履约订单 1 单 / 645 元、接受报价 1 份且转单 1 份、取消预约 1 条；标注履约金额不是收款。

实际单据：报价 `1e0bbdae-c0da-4acb-8de1-c85c1d8aa5ae`，取消订单 `306f9545-82fc-47ce-a64c-1b08050ae846`，履约订单 `c830e833-13c4-402b-b227-b30c1729f622`，预约 `98c37a77-13d9-4fe7-ab73-afc6b1e9b556`。自动测试另覆盖 CRM 关联、金额快照、过期报价、权限、多空间、版本冲突、批量原子失败及幂等。

## GPT 只读业务查询

员工可显式启用本地商品与时段查询，默认关闭。仅服务器筛选的事实进入模型；产品编号精确过滤，历史引用重新读取最新值，生成后再检查版本。模型无库存/订单写入权限；必须实际人工确认，不能靠模型文字改状态。查询结果注明 CNY、金额单位分、时间单位、当前本地事实和非完整目录。

真实 Hermes → Codex `gpt-6.1-sol` 验收：中文价格库存、英文查询、无货、未知编号、时段容量、要求直接预约、取消退款、诱导下单付款，以及三轮「询价 → 两件合计 → 改一件要求下单」。10 项行为检查通过（其中退款诉求由规则直接交人工，其他路径真实调用模型）；没有创建订单/预约，库存不变。普通询价保留 AI 接待，两件正确计算 258 元，实际下单请求转人工。

早期模型对普通询价也提前交人工，已调整提示并复测；另发现英文回复未明确币种，已补充明确 CNY 事实字段。模型回归不是确定性安全证明，安全边界由无写权限和服务器事务保证。原始报告保留于 `commerce-gpt-1HwJ6p/report.json`（币种字段补充前，后续桌面连接单测成功）。桌面模型设置真实连接测试：2756 ms、15 tokens。

## 完整备份与恢复

维护面板新增完整备份与恢复。备份数据库、附件和本机密钥文件；不导出 Hermes 登录令牌。停止本客户端后端后复制一致性 SQLite 快照，校验各文件 SHA-256 和数据库完整性。拒绝符号链接、路径越界与损坏备份。恢复前自动再做一个可选择的完整备份，同时保留原数据目录。恢复日志用于中断回退；启动失败自动恢复原数据。备份不会上传，也不自动删除。
